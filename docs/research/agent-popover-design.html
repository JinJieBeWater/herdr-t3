子 agent 菜单，是当前工作的局部入口。

这套布局让人同时开着很多 agent，只看需要他的那几个。这里回答的是“它派出去的 agent 怎么样了，打开哪个看看”。因此沿用紧凑菜单，不把项目与机器信息升级为每行常驻的第二行。

Inbox按注意力组织：什么需要我，什么可以收起。
Lists按项目组织：有哪些 space 和 agent，分别在哪里。
标签与窗格当前工作上下文；标题栏状态包含仍在运行的子树。
子 agent 菜单查看当前 agent 的派生关系、各自状态，并 peek 一个。

为什么保留详情卡

  • 这是整套布局已有的次级信息层。Inbox 与 Agents 都把 space、机器、分支、程序放在共用详情卡，当前入口继续使用。
  • 子 agent 可能跨机器，或有自己的 pane 和分支。不能假设它与父级同处一地，也不能把这些字段删掉。
  • 完整名称用于确认详情属于哪一行。此处的重复有归属作用；详情卡时序也应沿用共享规则，不单独延迟或换成新面板。
