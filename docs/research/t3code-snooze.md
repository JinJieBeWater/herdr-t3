# T3 Code 侧栏 Snooze 研究

## 结论先行

- **Snooze 是有期限的临时收纳**：把暂时不需要关注的线程从 Inbox 收起，到指定时间回来；线程和后台工作继续存在。T3 Code 移动端 Snooze PR 说明其目的为 “temporarily remove inactive threads from the main list without archiving or deleting them”，保留查看和恢复入口。[PR #5053：Why](https://github.com/pingdotgg/t3code/pull/5053) · [`effectiveSnoozed` 与唤醒条件](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/packages/client-runtime/src/state/threadSettled.ts#L81-L97)
- **它和其他侧栏动作各司其职**：Settle 表示工作已收尾，进入 Settled；Pin 表示要持续置顶；Archive 则是归档并离开默认线程列表。Snooze 暂时隐藏但保留线程，未来自动回来，也可因需要用户处理而提前回来。[Settle 清除 snooze 和 pin](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/apps/server/src/orchestration-v2/Orchestrator.ts#L3485-L3504) · [Pin 清除 snooze/Settled](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/apps/server/src/orchestration-v2/Orchestrator.ts#L3544-L3559) · [Archive 与 unarchive](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/apps/server/src/orchestration-v2/Orchestrator.ts#L3472-L3484) · [默认列表排除 archived](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/apps/mobile/src/features/threads/threadListV2.ts#L667-L673)
- **Snooze 是线程状态，不是只存在于 UI 的计时器**：Orchestrator 保存 `snoozedUntil`、`snoozedAt` 并发出 snoozed/unsnoozed 事件，服务端校验期限和线程是否可 snooze；所有连接客户端从线程 shell 得到此状态。[合同字段/事件/命令](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/packages/contracts/src/orchestrationV2.ts#L477-L489) · [Shell 投影](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/apps/server/src/orchestration-v2/ProjectionStore.ts#L1600-L1613) · [服务端处理](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/apps/server/src/orchestration-v2/Orchestrator.ts#L3406-L3451)
- **Herdr 的可行最小版**：在既有 terminal label 机制上增加 `snoozed=<wake_ms>:<turn>`，UI 依当前时间决定 Inbox 或 Snoozed；定时刷新到期项，提供显式唤醒入口。需接受 terminal label 的范围和同步限制，并决定如何从 pending/blocked 状态提前唤醒。**这是基于 Herdr 现有代码的推断，不是 T3 Code 事实。**[Herdr Settle label 写入与读取](../../mods/t3-inbox/main.js#L124-L134) · [Herdr 当前回归规则](../../mods/t3-inbox/main.js#L155-L167)

## 目的与状态分工

- **Snooze**：设定未来唤醒时间，暂时从正常 Inbox 隐藏；评论明确：“a snoozed long-running thread keeps waking itself for background work and stays hidden until its timer.”只有需要用户处理或新失败等条件才提前唤醒。[注释与条件](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/packages/client-runtime/src/state/threadSettled.ts#L81-L97) · [移动端 PR 对工作不被归档/删除的说明](https://github.com/pingdotgg/t3code/pull/5053)
- **Settle**：把完成的工作放入 Settled 收纳区；新工作可让线程回来。Settle 原子清掉 Pin 与 Snooze 字段。[Settle 状态更新](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/apps/server/src/orchestration-v2/Orchestrator.ts#L3485-L3504)
- **Pin**：持续把线程保留在顶部。Pin 会从 Snoozed/Settled 提升出来并清除相应状态；Pin 不阻止自动 Settlement。[Pin 状态更新](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/apps/server/src/orchestration-v2/Orchestrator.ts#L3544-L3559) · [产品说明：Pin 不阻止 automatic settlement](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/docs/user/thread-sidebar.md#L77-L77)
- **Archive**：归档线程；其 `archivedAt` 与 Snooze 分开存储，默认列表过滤 archived 线程。不是到期自动恢复的临时收纳。[Archive 更新](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/apps/server/src/orchestration-v2/Orchestrator.ts#L3472-L3484) · [默认列表过滤](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/apps/mobile/src/features/threads/threadListV2.ts#L667-L673)

初始功能提交可追踪为 `feat(sidebar-v2): thread snoozing (#4311)`；其历史服务端 decider 测试及初始 schema 在提交变更列表中。[初始提交](https://github.com/pingdotgg/t3code/commit/202e5609ffb294bc0aa86c08ce1d3751de567226) 当前代码注释和移动端 PR 给出的动机更明确：暂时收起 inactive thread，减少 Inbox 干扰，同时让用户可检查并恢复。[客户端注释](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/packages/client-runtime/src/state/threadSettled.ts#L81-L84) · [PR #5053](https://github.com/pingdotgg/t3code/pull/5053)

## 实现机制

### 数据与命令

- 线程模型存 `snoozedUntil`（UTC 到期时间）、`snoozedAt`（何时 snooze）；另有 `lastSnoozeWakeAt` 记录唤醒时间。字段位于 Orchestration V2 app-thread 与客户端 thread shell；服务端把字段投影进 shell，客户端据此同步显示。[线程字段](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/packages/contracts/src/orchestrationV2.ts#L474-L490) · [Shell 字段](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/packages/contracts/src/orchestrationV2.ts#L2125-L2137) · [投影输出](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/apps/server/src/orchestration-v2/ProjectionStore.ts#L1600-L1613)
- 合同命令是 `thread.snooze { threadId, snoozedUntil }` 和 `thread.unsnooze { threadId, reason: "user" }`；事件分别为 `thread.snoozed` 和 `thread.unsnoozed`。[命令 schema](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/packages/contracts/src/orchestrationV2.ts#L2982-L2993) · [事件 schema](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/packages/contracts/src/orchestrationV2.ts#L1870-L1885)
- 服务端拒绝过去或无效的 wake time；有 pending approval/user-input request 或普通 queued run 时也拒绝 snooze。例外是 notification/delegated-completion 形成的自动 queued run，因为它代表后台工作，不应使用户设的 Snooze 失效。[校验逻辑](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/apps/server/src/orchestration-v2/Orchestrator.ts#L3406-L3451)

### 互斥、自动唤醒与“raises its hand”

- Settle 清除 Snooze 和 Pin；Pin 清除 Snooze 并把 Settled 线程提升为 active；Snooze 不会通过单纯的后台 run 完成而清除。显式 Un-snooze 清除 snooze 字段。[Settle/Pin/Unsnooze 更新](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/apps/server/src/orchestration-v2/Orchestrator.ts#L3485-L3559) · [后台唤醒不清 Snooze 的注释与新消息处理](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/apps/server/src/orchestration-v2/Orchestrator.ts#L5544-L5565)
- 新的用户消息会清掉 `snoozedUntil` / `snoozedAt`；自动通知或 delegated completion 则继续保留 Snooze。[新消息类型判断](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/apps/server/src/orchestration-v2/Orchestrator.ts#L5544-L5565)
- 客户端 `threadRaisedHandWhileSnoozed` 会立即解除隐藏的条件：pending approval、pending user input、runtime request、subagent request、guest message，或发生在 `snoozedAt` 之后的新 failure。普通 run 成功完成不算举手；失败时间优先取 failed run 的 `completedAt`，避免 runtime 元数据更新误判为新失败。[raised-hand 判定与 failure edge](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/packages/client-runtime/src/state/threadSettled.ts#L81-L109)
- `effectiveSnoozed` 是 `snoozedUntil > now` 且没有 raised hand。时间到期或提前举手会让线程离开 Snoozed shelf；计时到期本身可只在客户端重分区，不依赖服务端某个定时命令。[有效状态](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/packages/client-runtime/src/state/threadSettled.ts#L137-L171) · [侧栏精确 wake clock](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/apps/web/src/components/Sidebar.logic.ts#L126-L155)
- Web 为最近一个未来 wake time 设置 deadline，到点更新 clock 并重新分区；系统睡眠期间漏过多个 deadline 会跳到最新已过期时刻。Mobile 每分钟更新 clock，并另外为下个 snooze deadline 更新，不会被 minute tick 最多拖延一分钟。[Web clock](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/apps/web/src/components/Sidebar.logic.ts#L126-L155) · [Mobile clock](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/apps/mobile/src/features/threads/use-thread-list-now.ts#L6-L23)
- 醒来后按普通分区重新出现：Active/Working 由当前 run 与列表设置决定；用户消息会清除 snooze。显式 Wake 也是 unsnooze。来源没有规定统一的“醒来排第几”位置，Active 排序依其现有排序模式。[分区优先级与排序](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/apps/web/src/components/Sidebar.tsx#L659-L727) · [移动端 Active/Working 分类](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/apps/mobile/src/features/threads/threadListV2.ts#L698-L721)

## Herdr Inbox 的最小映射（推断，不是 T3 事实）

Herdr 当前 Settle 用 `settled=<ms>:<turn>` terminal label；通过 `hc label` 写入，暂存 `pending` 让 UI 先响应，再等 label 从 core 回读。Settle 时间与 turn 都随每个 agent/terminal 保存。[Herdr 写入与 pending](../../mods/t3-inbox/main.js#L124-L134) · [label 读取](../../mods/t3-inbox/main.js#L155-L159) · [Settle 值](../../mods/t3-inbox/main.js#L230-L245)

### 建议的最小实现

1. 复用 label 通道写入/清除 `snoozed=<wake_ms>:<turn>`；只让已完成、未 pinned 的 agent Snooze，避免对 Working agent 提供与当前 Settle 一致性相冲突的操作。[当前 Settle gate](../../mods/t3-inbox/main.js#L240-L245)
2. 在 `render` 读取 snoozed label，按 `wake_ms > now` 划分 Snoozed 收纳区；到期即按普通 Active/Working 规则显示。用下一个 wake deadline 更新列表，避免只能等下一次无关 render 才回来。Snoozed 按 wake 时间升序；行显示剩余时间，hover 显示 Wake/取消入口。
3. 记录 Snooze 时的 turn；若 agent 开始工作或 turn 增加则清除 snooze label，沿用当前 Settle 的“新工作唤回”模式。[当前自动 Un-settle 判定](../../mods/t3-inbox/main.js#L160-L167)
4. Snooze 与 Pin/Settle 互斥：沿用 Pin/Settle 优先，并在显式 Pin/Settle 时清掉 snooze label；显式 Wake 清空 snooze label。Archive 不是本地 Inbox 的现有状态，无需借用 settled label 表达。

### Herdr 与 T3 的关键差异

- `hc label` 写在 agent 所属 terminal 上，存于 herdr-core：连到同一个 core 的每个 Herdr 客户端都看得到（Herdr 对置顶的说明：“Pins are kept with the terminal, so every Herdr client shows them”），这一点与 T3 服务端 projection 的多端一致相当。差别在寿命：Herdr 当前 Settle 注释指出它“ends with the terminal”，终端结束 Snooze 也随之消失；T3 的 Snooze 跟着线程持久保存。[Herdr 说明](../../mods/t3-inbox/main.js#L1-L4) · [T3 服务端 shell 字段](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/apps/server/src/orchestration-v2/ProjectionStore.ts#L1600-L1613)
- 现有 Herdr `busy()` 只按 agent/子 agent 的 `BUSY` 状态判断。T3 的“raises its hand”更细，包含 approval、用户输入、runtime 请求、guest/subagent request 和新失败；不要把两套可唤醒条件说成等价。[Herdr busy 判定](../../mods/t3-inbox/main.js#L160-L163) · [T3 条件](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/packages/client-runtime/src/state/threadSettled.ts#L86-L108)
- T3 的日历 preset、跨 DST、设置同步和多端一致性对于最小 Herdr 版本都不是必须项；如果先要的是“稍后从 Inbox 回来”，只需提供一两个时长选项、Wake 操作和到点刷新。添加“明天早上”等本地时刻选项时，再采用日历日计算而非固定 24 小时偏移。[T3 preset 日历计算](https://github.com/pingdotgg/t3code/blob/cefb544af3c98224874419198c0359b652ca3c94/packages/client-runtime/src/state/threadSettled.ts#L202-L280)
