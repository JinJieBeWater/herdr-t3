# Herdr 体验需求交接：详情、面板标签与壁纸构图

整理日期：2026-11-13。范围来自当前空间各会话的原始需求与已确认选择。本文按最终目标组织，接手者无需追溯会话、agent 分工或实施过程。

配套 [show-me 交互示意](show-me-experience-requirements.html)。**本文是需求依据；HTML 用来解释布局与交互，不代表 Herdr 已实现这些行为。**

标记含义：**已确认**是用户已有的选择；**建议默认**是为交接补齐的实现建议，可在开发时按上下文调整；**待验证**是宿主能力或验收缺口，不是新增产品需求。

## 1. 整体目标与分工

把日常工作入口整理为三块：右上角详情提供当前工作上下文与 Actions；右侧 space 面板承载多个文件标签和唯一的 Review；Home 的图片导入在保存前完成构图。

| 工作包 | 用户得到什么 | 主要边界 | 依赖 |
| --- | --- | --- | --- |
| A · 详情与布局控件 | 两个明确入口；详情按需弹出，面板开关在窗口右上角 | 入口位置、三行详情、焦点、现有 Actions | 与 B 共同涉及面板头，先约定职责 |
| B · 动态面板标签 | 每个文件一个标签；Review 一个；可添加、切换和关闭 | 标签状态、文件选择、关闭与菜单 | 沿用第 4 节阅读规则 |
| C · 壁纸导入构图 | 新图片固定 Dots；导入时定位、缩放；Apply 后固定 | 导入草稿、构图、保存与失败恢复 | 可与 A/B 独立实施 |

这些工作包是交付拆分建议，不要求创建新的抽象层或重写已有模块。当前任务只整理交接材料。

## 2. A · 详情与布局控件

### A1. 布局与入口（已确认）

```text
面板关闭  主工作区标题                           [详情] [面板]
面板展开  主工作区标题 [详情] │ [文件标签…] [Review] [+] [放大] [面板]
面板放大                       [文件标签…] [Review] [+] [恢复] [面板]
```

- 详情入口属于主工作区；面板开关位于窗口右上角，打开面板后由面板头承载。
- 放大／恢复只在面板打开时出现；放大隐藏工作列，恢复回到并排。平台需要的原生窗口按钮继续在最右侧正确显示。
- 详情在所有宽度下默认收起，点击才打开原生 popup。打开和关闭详情不改变终端尺寸、分屏或 zoom，不预留常驻卡片的位置。
- 详情入口和面板入口是两种操作；详情内容不成为面板标签。

### A2. 详情严格三行（已确认）

| 行 | 必须出现的内容 | 操作 |
| --- | --- | --- |
| 机器／目录 | 本机或当前 space 的真实远程机器名；当前工作目录 | 完整路径提示、复制目录；下拉复用现有 space 菜单 |
| Open in | 当前目录的可用打开目标 | 本机先支持系统文件管理器；多个真实可用目标才显示选择箭头 |
| Actions | 现有“上次使用的动作／下拉”按钮组；没有动作时 Add action | 运行、选择、新增、编辑、删除，显示完整动作名 |

机器属于 space 的事实；机器行不提供把现有终端迁往另一台机器的操作。远程目录不能交给本机 Finder：仍可复制路径，不可用的 Open in 显示原因。

详情不加入 Todo、agent 状态、space 概览、Review、Git 操作或底部终端。

### A3. 执行与焦点（已确认）

- 打开详情时确定来源 space／tab／terminal；目录优先当前终端 cwd，再同标签终端，最后 space folder。
- Actions 保留现有数据、图标、Tab／Right／Down 运行位置、显式 cwd 与编辑／删除确认。动作执行目录优先动作自己的 cwd，再用上述来源上下文。
- popup 获得焦点后，执行目标仍是打开详情时的来源。切换 space／tab 后来源失效，关闭并提示重新打开，不能在旧位置执行。
- Actions 子菜单的 Escape 先关子菜单，再一次关详情。执行动作或进入编辑器前收起对应弹层；关闭后恢复适当焦点。
- 点弹层外关闭详情；普通外点保留右侧面板。关闭 popup 的按键不能连带关终端标签。
- `cmd-shift-b` 改为切换详情；Inbox／Lists 通过原有侧栏按钮切换。`cmd-alt-b` 切面板、`cmd-shift-g` 切 Review；B 中面板内的 `cmd-w` 关闭活动标签。
- 面板放大时通过详情快捷键进入，先恢复工作列，再弹出详情。Home 沿用其原有 Actions 上下文规则。

### A4. 验收

1. 本机与远程的三行内容、空 Actions 和多个 Actions 都正确；目录和动作运行位置可核对。
2. 详情开关前后，终端的尺寸、分屏和 zoom 一致。
3. 嵌套 Escape、外点、动作编辑／删除和来源失效可回放，背后的终端不被误关。
4. 面板关闭／展开／放大只有一组正确的布局及平台按钮；装与不装 Review 扩展都能正常显示。
5. 默认侧栏宽度、窄窗、明暗主题下整窗内容完整。macOS 以外的窗口控件需对应平台验证。

## 3. B · 动态面板标签

### B1. 内容模型（已确认）

```text
space 面板
├── 标签条：[a.md ×] [b.js ×] [Review ×] [+]     [放大] [面板]
└── 当前内容
    ├── 文件标签 → 一个共用的 Files 视图，显示该标签对应文件
    └── Review   → 一个 Review 视图，在内部切范围、分组和 diff 文件
```

每个 space 保存自己的面板开关、放大状态、标签列表和当前标签；同一 space 切换终端标签时面板内容不变。面板宽度仍是整个窗口一份。

文件标签共享一棵 Files 文件树，不为每个标签各建树或 mod 副本。Review 在面板中最多一个；点击 Review 树里的文件仍是在 diff 内定位，不创建文件标签。

### B2. 操作规则（已确认）

| 操作 | 结果 |
| --- | --- |
| 打开空面板 | 标签区域只有 `+`，可选 Files 或 Review；没有安装 Review 时只提供可用项 |
| `+ → Files / Review` | 添加对应入口；已存在对应入口时切过去 |
| 第一次在 Files 树中打开文件 | 用文件标签替换通用的 Files 标签 |
| 再打开其他文件 | 每个不同文件新增一个标签 |
| 打开已存在的文件 | 激活已有标签，不重复创建 |
| 点面包屑里的文件夹 | 在共用文件树中定位，不开文件夹标签 |
| 点文件标签 | 切到这个文件，Files 树选中它 |
| 点 Review 标签 | 恢复 Review 自己的范围、组、文件和阅读位置 |
| 标签的 `×`／中键 | 关闭被操作的标签 |
| 面板有键盘焦点时 `cmd-w` | 关闭活动标签，不能关闭背后的终端 |
| 关闭活动标签 | 激活原位置的下一个标签 |
| 关闭最后一个标签 | 收起面板 |
| 面板开关 | 只隐藏／重新显示面板，保留尚未关闭的标签 |

右键菜单：**Copy path**（仅文件标签）、**Close**、**Close others**、**Close to the right**、**Close all**。

### B3. 交接补齐的建议默认

原记录没有逐项确定以下边缘行为；建议采用下面的最小一致规则，并在实现文档中明确。

- 关闭最右的活动标签时，没有右邻就激活左邻；关闭非活动标签保留当前标签。
- 文件标签已经存在时，`+ → Files` 激活最近的文件标签；不再重复创建通用 Files 入口。
- 关闭最后一个标签后再按面板开关，显示空面板和 `+`。
- 文件标签变多时横向滚动，保持活动标签可见；首版不另加拖动排序或重开历史。
- 各文件的阅读位置按需保留；完整内容缓存继续服从第 4 节的资源边界，避免每开一个标签就永久持有一个 Editor。

### B4. 首版边界与待验证

首版不含 `cmd-shift-t` 重开、拖动排序、终端／浏览器／PR 标签或每个标签各自一棵树。

宿主的中键和右键事件、标签区域的键盘上下文需先在 demo 验证。标签列表和各文件阅读位置的具体持久化表示属于实现选择；下列只是原讨论的状态草图，不是必须复制的数据协议：

```text
t3.panels[space] = { open, wide, tabs: ["file:docs/a.md", "file:src/b.js", "review"], active: "file:src/b.js" }
```

### B5. 验收

1. 从空面板开始，加 Files、点两个文件、重复点第一个，只得到两个文件标签；Review 始终只有一个。
2. Review 树内跳转不影响 Files 标签，切回 Files 恢复自己的文件；面包屑文件夹只在树内定位。
3. 回放当前／非当前／最右／最后标签的关闭，以及全部右键关闭项；验证中键与 `cmd-w` 的真实事件。
4. 隐藏再开、放大再恢复、切 space 再返回，都恢复对应状态；空面板仍可用 `+`。
5. 长文件名和大量标签不会挤掉 `+`、放大和面板开关；默认侧栏宽度及窄窗整窗验收。

## 4. Files / Review 的共同约束

这里是 A/B 要保留的最终阅读模型，已由 ADR 0012–0015 收敛。接手时对照当前实现补缺口，避免照旧计划重做。

| 主题 | 最终要求 |
| --- | --- |
| 归属 | 窗口右侧一个 space 面板，跨终端标签；每个 space 恢复自己的内容 |
| 页面独立 | Files 浏览工作目录，Review 阅读选定变更范围；各自保留阅读位置、导航宽度与换行偏好 |
| 切页 | 手动选择目标标签和该页文件；取消 Open in Files / Open in Review 等隐式跨页请求 |
| 外框 | 相同卡片、常驻工具栏、左内容右导航；复用树行、菜单、加载／空／错误组件与主题样式 |
| Review 分组 | 工具栏下方整页一行组页签；含类别、名称、critical、增删数、文件数和已看进度；单组隐藏，多个组横向滚动 |
| 组筛选 | 选组后 diff 与文件树都只显示当前组；子组在树内；规则分组和 AI 分析分组都保留 |
| Review 范围 | 页内顶栏选择 Changes、Uncommitted、To push、To pull、Commits、Branches；上游相关项按真实可用性显示 |
| Review 能力 | 保持只读，保留 AI 分组／逐行说明、已看标记、整文件展开、大 diff 分批和现有阅读快捷键；阅读设置支持换行 |
| 菜单 | Commits／Branches 和设置子项采用侧向子菜单，支持搜索、键盘进退和靠边翻转；真实斜移需实测 |
| 文件树 | 单一当前文件；目录优先、忽略大小写的自然排序；共用紧凑行、目录压缩与键盘导航 |
| 本地／远程 | Files 支持两者；Review 以其现有本机 daemon 能力为界，不借本轮增加远程 Review |
| 文件预览 | 只读代码、Markdown Preview／Code 和图片；文本上限 1 MiB，远程图片上限 512 KiB；搜索按路径 |
| 生命周期 | 只在对应页面、space、窗口可见时读刷；本地通常 5s、远程 10s，Review 15s；显示时补读，大仓库适当放慢 |
| 资源 | 每页最近三个 space 保留完整数据，更早释放内容／Editor／diff 缓存，保留轻量阅读设置 |
| 监听 | 沿用可见时轮询；现有 watchFolder 的未决订阅不能可靠撤销，递归 watcher 不作为本次前置依赖 |

不加入选行批注交给 agent、GitHub PR 评审、stage／commit／push、文件编辑／新建／改名／删除或全文搜索。

## 5. C · Home 壁纸导入构图

### C1. 用户已确认的流程

```text
选择图片 ── 固定生成 Dots ── 构图预览 ── Apply ── 固定显示
选择 .ans ── 保留字符画法 ── 构图预览 ── Apply ── 固定显示
                                  └── Cancel ── 返回原壁纸
```

- 新图片固定使用第三种 **Dots**，去掉图片导入的 Braille／Blocks／Dots 三选一。
- 位置和铺放方式只在导入时调整，Apply 后固定，日常画面不进入拖动编辑。
- Studio `.ans` 保留原来的字符画法。移除图片风格选择不等于移除已有 `.ans` 的 Braille／方块字形渲染。
- 已保存壁纸与内置画保留；日常仍可切换、添加、确认删除。
- 直接把 `.ans` 放进壁纸目录仍按默认构图载入，不自动弹出导入预览。

### C2. 构图控件（原计划的建议默认）

| 控件 | 行为 |
| --- | --- |
| 填满 cover（默认） | 保持比例铺满，允许裁切 |
| 完整显示 contain | 1 倍时展示整张图，允许留白 |
| 拖动／键盘定位 | 调整图在画布中的位置 |
| 缩放 | 所选铺放基准的 1–4 倍；contain 放大后允许裁切 |
| 重置 | 恢复该铺放方式的默认位置和倍率 |
| Apply / Cancel | 提交构图或丢弃草稿 |

用户确认了“只在导入时调整构图”；cover／contain 的具体组合、默认值和 1–4 倍是原方案建议，接手者应按此最小方案交付并明确这些默认值。

### C3. 保存与失败恢复

- 保存相对位置、铺放方式与缩放倍率；窗口／侧栏尺寸变化后按同一规则计算。固定的是构图参数，不是旧窗口的像素截图。
- 预览和应用后的显示使用相同计算。拖动、缩放不反复转换或重写 `.ans`。
- 草稿留在内存，Apply 后才写持久构图。构图与可重建的 SVG 缓存分离，缓存重建不能丢失用户构图。
- 最终文件与缓存就绪后才更新构图和选择。Apply 失败保留草稿和重试入口，当前选择不变；Cancel 回到原壁纸。
- 沿用现有原子发布、不覆盖目标、删除确认和异步草稿失效机制；两 Home 并行、连续选图、取消及转换中删除不能让迟到任务覆盖新选择或复活已删除文件。
- 没有构图记录的旧壁纸继续按原规则显示；删除对应壁纸时清理其构图记录。

### C4. 验收与首版边界

1. 新图片预览和最终保存均为 Dots；旧 Studio／Braille／Blocks `.ans` 正常显示。
2. 横图、竖图和方图在填满／完整显示下保持比例；拖动、键盘、缩放和重置符合说明。
3. Apply 后与预览一致；重开 Home、重启、换主题、调窗口／侧栏后构图参数有效，日常无法拖动编辑。
4. 回放 Cancel、Apply 失败重试、同名冲突、连续选图、两 Home 并行和转换中删除。
5. 在隔离桌面做真实拖动和缩放验收，留默认侧栏宽度的完整窗口证据。

首版不含平铺、拉伸、旋转、保存后重新编辑或历史壁纸批量转换。Home 久置后闪空白另属故障诊断，不混入本次构图需求。标题里出现过“深浅主题配置”，原始材料没有据此形成独立的新增主题需求；这里只保留现有主题切换下的显示要求。
