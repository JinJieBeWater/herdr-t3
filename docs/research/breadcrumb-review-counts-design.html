面包屑里的 Review 计数

结论（2026-11-11）：都不放。面包屑只管导航（在哪、去那个 space），挂上 git 状态和 Review 入口会让它一个控件干三件事；旁加的图标、胶囊又和路径格格不入。标签栏只留面板按钮，分析状态在按钮里、图标左边；这个布局里不再为计数读 git。要看数量：Spaces 行的 ↑↓，Review 页的范围菜单。

同一行标签栏，按真实尺寸画（40px 高，面包屑 14px medium，Catppuccin Mocha）。用户的要求：git 状态要融进面包屑本身，否则不如不要。所以只有 D 是候选，A–C 留作对照。

没有新控件：分支就是路径里的一级（space / 分支 / agent），和 space 段同一个字号、字重、颜色、悬停方式；状态用编辑器和 shell 通用的写法贴在分支名上：* 有未提交改动（VS Code 的 main*），↑n ↓n 待推/拉（Spaces 行已经这样写）。分析在跑时转圈跟在后面，完成是圆点、失败是 !，和 tab 上 agent 的标记一样；面板按钮回到纯图标。
数字只留 ↑↓：未提交的文件数、比默认分支多几个提交放进悬停说明卡和 Review 页的范围菜单，不占路径。点分支段在 Review 页打开它最相关的范围（有未提交就 Uncommitted，否则这个分支对默认分支的 Changes），和点 space 段开标签一样是“去那里”。不在 git 仓库里时没有这一段。Lists 没有面包屑，不显示。
